# Phase 2: 1on1・進捗・継続支援ロジック

## 1. 1on1準備

AI入力候補は、前回1on1以降の確定差分、目標状態、行動の完了・遅延、本人自己評価、現場経験、成果・証拠、障害、未完了宿題である。機密・AI送信禁止を除外し、全履歴ではなく差分を優先する。

出力は以下を分離する。

- 確認済み事実の要約
- 前回からの変化
- 未確認・矛盾・情報不足
- ULが尋ねる質問候補と意図
- 目標継続・修正・保留の検討候補
- 次の行動候補
- Member本人へ確認すべき事項

「問題がある」「意欲が低い」等の断定は禁止し、観察可能な事実と確認質問へ変換する。ULは提案を採用、編集、却下し、会話の最終判断を行う。

## 2. 1on1中・後

MVPではAIが会議へ自動参加・録音・リアルタイム評価しない。ULが必要なメモを入力し、通常・機密・AI送信禁止を指定する。終了後AIは決定候補、Memberの発言候補、UL観察、宿題、期限、目標変更候補を分けて整理する。ULが原文と照合して確定し、目標変更はMember確認後にのみ反映する。

## 3. 進捗モデル

| 要素 | 内容 |
|---|---|
| 状態 | 未着手、進行中、停滞、完了、保留、中止 |
| 定量進捗 | 適用できる場合のみ0〜100%。根拠を保持 |
| 本人自己評価 | Memberの自己申告。AI評価と分離 |
| 証拠 | 成果物、URL、説明、日付、確認者 |
| 障害 | 事実、影響、解消候補、支援要否 |
| 次回確認 | 目標ごとの日付・周期・理由 |

AIは前回との差分、期限との関係、未完了行動、障害の継続を整理する。成果不足を能力不足と推定しない。

## 4. リマインダー

通知日程の計算と配信は決定論的なアプリ機能とし、AIは頻度候補と理由だけを提案する。対象は行動予定、中間確認、振り返り、1on1、SMART再確認、目標期限、目標更新、未回答。

- 目標ごとに周期、通知先、猶予、停止条件を設定できる。
- 通知過多を防ぐため同日・同対象を集約し、スヌーズ・停止を可能にする。
- 期限超過を評価低下として表現しない。
- 土日祝日を休日とする業務期限は日本の祝日カレンダーを用いる。
- 交通費提出期限は「翌月第2営業日」とし、参照資料の古い記載より優先する。
- レスポンススピード規則は「24時間応答がない」状態を対象とする。

## 5. 目標変更

変更検討の契機は、本人の価値観・生活条件の変化、現場・役割変化、継続障害、前倒し達成、期限到来、定期レビュー、本人の違和感である。AIは次を提示できる。

- 継続、範囲縮小・拡大、期限変更、行動変更、保留、中止の候補
- Why・将来像への影響
- 制度関連がある場合の影響（正式評価ではない）
- 変更しない選択肢

確定目標を直接上書きせず、新版、変更理由、差分、Member確認、UL記録を残す。

## 6. 次課題・行動生成

候補は未達を埋めるだけでなく、本人が望む方向、現在の余力、現場で得られる経験、小さく試せる行動を考慮する。各候補に目的、期待効果、負荷、期限候補、証拠、前提、代替案を付ける。会社KPIとの関連は任意であり、関連づける場合は本人への価値を説明する。

## 7. 達成後

達成時は成果・学び・本人の感情・Whyへの寄与・次に続けることを振り返る。即座に次目標を強制せず、継続、休止、探索、次の通過点を選択可能にする。

## 8. 例外・境界

- Memberが発言を撤回した場合、将来利用から除外し履歴上の取扱いを明示する。
- UL交代・Unit異動時は権限移行を先に行い、旧ULの非公開メモを自動移管しない。
- Unit兼務は原所属Unitを基準とする。退職率は会社退職時の原所属、休職者除外、再入社者も退職イベントを維持、統合・分割は期末所属、8名以上判定は評価期間の平均人数8.0以上とする。
- 危機・健康・ハラスメント等が示唆されてもAIは診断・自動通報しない。一般的な安全案内と社内の人間窓口への確認を促し、ULが判断する。
- AI停止時はULがテンプレートと確定履歴を使って準備・記録・共有できる。
