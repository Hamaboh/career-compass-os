# Phase 1: 機能要件・非機能要件

## 1. 記法

- `MUST`: MVP必須。
- `SHOULD`: MVPで優先するが、Design Freezeで調整可能。
- `MAY`: 将来候補。

## 2. 機能要件

### 2.1 認証・利用者

| ID | 優先 | 要件 |
|---|---|---|
| FR-AUTH-001 | MUST | Google Workspaceを認証元としてログインできる |
| FR-AUTH-002 | MUST | 認証済みでもアプリ未登録・無効利用者を拒否する |
| FR-AUTH-003 | MUST | ロール、Unit scope、記録機密区分をAPIで検証する |
| FR-AUTH-004 | MUST | ULは自Unit、上位役職者は全Unitを読み取れる |
| FR-AUTH-005 | MUST | 上位役職者は元データを直接編集できない |

### 2.2 Unit・Member

| ID | 優先 | 要件 |
|---|---|---|
| FR-MEM-001 | MUST | ULが自UnitのMemberを手入力で登録・更新できる |
| FR-MEM-002 | MUST | 主所属、兼務、在籍、休職、入社、退職の履歴を扱える |
| FR-MEM-003 | MUST | 兼務者を主所属Unitの人数だけに計上できる |
| FR-MEM-004 | MUST | 退職・休職・Unit異動を履歴として保持できる |
| FR-MEM-005 | MUST | 上位役職者が全Unit・Memberを読み取れる |

### 2.3 本人理解・将来像

| ID | 優先 | 要件 |
|---|---|---|
| FR-SELF-001 | MUST | 本人の経験、感情、生活上の希望、働き方、興味、強み、課題を記録できる |
| FR-SELF-002 | MUST | 本人発言、UL所見、AI推測を分離する |
| FR-SELF-003 | MUST | 将来像を仮説・確認済み・保留として保持できる |
| FR-SELF-004 | MUST | 未回答・答えたくない状態を許容する |
| FR-SELF-005 | MUST | 明確な目標がある場合は自己分析全工程を省略できる |

### 2.4 目標・Why・行動

| ID | 優先 | 要件 |
|---|---|---|
| FR-GOAL-001 | MUST | 幸福、ライフ、キャリア、将来像、Why、目標、行動、成果、振り返りの関連を扱える |
| FR-GOAL-002 | MUST | 会社制度と関係しない目標を許容する |
| FR-GOAL-003 | MUST | 制度との関連を任意かつ版固定で記録できる |
| FR-GOAL-004 | MUST | SMART各項目をOK・要改善・不足で保持できる |
| FR-GOAL-005 | MUST | 期限、達成基準、中間確認日、確認周期を目標ごとに設定できる |
| FR-GOAL-006 | MUST | 下書き、本人確認待ち、確定、実行中、保留、完了、中止を扱える |
| FR-GOAL-007 | MUST | 変更前後、変更理由、確認結果を履歴化する |
| FR-GOAL-008 | MUST | 本人確認前の目標を正式目標として集計しない |

### 2.5 AI

| ID | 優先 | 要件 |
|---|---|---|
| FR-AI-001 | MUST | 目標形成の追加質問候補を生成できる |

### 2.6 1on1

|---|---|---|

| FR-1ON1-002 | MUST | 通常・機密・AI送信不可を設定できる |
| FR-1ON1-003 | MUST | 前回以降の差分・未完了を確認できる |

### 2.7 本人確認・レポート・共有

| FR-SHARE-003 | MUST | 確認日時、方法、承認・修正希望・保留、UL記録者を保持できる |
| FR-SHARE-004 | MUST | 既定7日・最大30日の期限付きURLを発行・失効できる |

### 2.9 レビュー・監査・運用

| ID | 優先 | 要件 |
|---|---|---|
| FR-REV-001 | MUST | 上位役職者がコメント、差戻し、確認済み状態を付けられる |

## 3. 非機能要件

### 3.1 セキュリティ・プライバシー

| ID | 要件 |
|---|---|
| NFR-SEC-001 | 認証、ロール、Unit scope、機密区分をサーバー側で強制する |
| NFR-SEC-002 | 推測ID・URL直接指定でもUnit越境を拒否する |
| NFR-SEC-003 | AI送信前の匿名化とUL承認を迂回できない |
| NFR-SEC-004 | Secret、token、個人情報をログ・エラーへ出さない |
| NFR-SEC-005 | 共有トークンを平文保存しない |
| NFR-SEC-006 | 期限切れ・失効共有をサーバー側で拒否する |
| NFR-SEC-007 | 学習不使用条件を確認できるAIだけを本番利用する |

### 3.2 可用性・復旧

| ID | 要件 |
|---|---|
| NFR-AVL-001 | 初期RPO 24時間を満たす |
| NFR-AVL-002 | 初期RTO 1営業日を目標とする |
| NFR-AVL-003 | AI停止時も既存データ業務を継続する |
| NFR-AVL-004 | バックアップを30日保持し、復旧手順を検証する |

### 3.3 性能・規模

| ID | 要件 |
|---|---|
| NFR-PERF-001 | 約12人の同時ではない通常社内利用を基準とする |
| NFR-PERF-002 | 通常一覧・詳細は実用的な待ち時間で表示する。具体値はPhase 3で定義する |
| NFR-PERF-003 | AI処理は非AI操作をブロックしない |
| NFR-PERF-004 | 同一入力のAI結果を再利用し、画面表示ごとに再生成しない |

### 3.4 コスト

| ID | 要件 |
|---|---|
| NFR-COST-001 | Cloudflare無料枠・低価格構成を優先する |
| NFR-COST-002 | AI費用を処理・利用者・モデル別に追跡する |
| NFR-COST-003 | 月間1,000円相当を初期上限とし、超過前に停止する |
| NFR-COST-004 | 高性能モデルを標準前提にしない |

### 3.5 UX・アクセシビリティ

| ID | 要件 |
|---|---|
| NFR-UX-001 | 一度に大量の質問を表示しない |
| NFR-UX-002 | AI提案、本人発言、UL所見、確定情報を視覚的に区別する |
| NFR-UX-003 | AI利用なしの手動経路を提供する |
| NFR-UX-004 | キーボード操作、ラベル、コントラスト等の基本アクセシビリティを満たす |
| NFR-UX-005 | 本人向けHTMLはスマートフォンと印刷で読みやすくする |

### 3.6 保守・監査

| ID | 要件 |
|---|---|
| NFR-MNT-001 | 制度、Prompt、AIモデル、共有スナップショットを版管理する |
| NFR-MNT-002 | 重要変更の理由と影響を追跡できる |
| NFR-MNT-003 | 正式・暫定・draft・未確認をデータ上で区別する |
| NFR-MNT-004 | 監査ログを3年間保持する |

## 4. 禁止要件

- AIによる自動目標確定。
- AIによる人事評価・給与・昇格・Course・配属判断。
- 本人未確認の目標を正式目標として扱うこと。
- フロントエンドだけのアクセス制御。
- 匿名化・UL承認を通らない外部AI送信。
- 上位役職者による通常データの直接上書き。
- 他Member・他Unit情報を本人向けHTMLへ含めること。
- 旧Phase 1〜4のDB・API・認証・技術構成をそのまま流用すること。
