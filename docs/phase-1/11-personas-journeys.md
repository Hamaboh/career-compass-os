# Phase 1: ペルソナ・As-Is/To-Be・ユーザージャーニー

## 1. ペルソナ

### 1.1 目標がないMember

| 項目 | 内容 |
|---|---|
| 状況 | 客先業務をこなしているが、将来像や目標がない |
| 困り事 | 何を目標にすべきか分からず、会社KPIをそのまま目標にしやすい |
| 必要な支援 | 過去経験、感情、生活上の希望、興味、避けたい状態から方向性を探索する |
| 成功 | 仮説の将来像と、次に試す小さな行動を本人が選べる |

### 1.2 目標はあるが曖昧なMember

| 項目 | 内容 |
|---|---|
| 状況 | 「AWSを頑張る」「上流へ行きたい」等の希望がある |
| 困り事 | Why、達成基準、期限、現状との差が不明確 |
| 必要な支援 | AI質問とUL対話で具体化し、SMARTと行動へ落とす |
| 成功 | 本人が目標と理由、次の行動を説明できる |

### 1.3 明確な目標を持つMember

| 項目 | 内容 |
|---|---|
| 状況 | 将来像、目的、期限がある程度明確 |
| 困り事 | 長い自己分析を繰り返したくない。実行管理と振り返りを効率化したい |
| 必要な支援 | ショートカットで目標案を入力し、不足だけAIが確認する |
| 成功 | 最小質問で品質監査を通過し、行動開始できる |

### 1.4 Unit Leader

| 項目 | 内容 |
|---|---|
| 状況 | 自身も客先稼働しながら複数メンバーを支援する |
| 困り事 | 目標設定質問、1on1準備、記録、次回アクションを毎回手作業で行う |
| 必要な支援 | AIによる質問・整理・SMART・要約と、未完了事項の一元化 |
| 成功 | 情報整理時間が減り、本人との対話と支援判断へ集中できる |

### 1.5 上位役職者

| 項目 | 内容 |
|---|---|
| 状況 | 全Unitの状況を把握し、ULを支援する |
| 困り事 | Unitごとの状態、目標品質、停滞、1on1運用状況を横断把握しにくい |
| 必要な支援 | 全Unitの読み取り、レビュー、コメント、差戻し、集計 |
| 成功 | 元データを破壊せず、支援が必要なUnit・ULを確認できる |

### 1.6 システム管理者

| 項目 | 内容 |
|---|---|
| 状況 | 約12人の利用者、Unit、制度、AI費用、監査を管理する |
| 困り事 | 過剰な運用負荷や高額なAI費用を避けたい |
| 必要な支援 | 少数利用者向けの簡潔な設定、利用量上限、監査、復旧 |
| 成功 | 小さな運用負担と予算内で安全に継続できる |

## 2. As-Is / To-Be

| 業務 | As-Is | To-Be |
|---|---|---|
| 本人理解 | 1on1ごとに断片的に聞く | 過去回答と変化をつなぎ、AIが不足質問を提示 |
| 将来像 | 明確な人だけ記録される | 不明確でも仮説として保存し、後から更新 |
| 目標設定 | ULの経験とテンプレートに依存 | 本人中心の対話 + AI質問 + SMART監査 |
| 制度接続 | KPIをそのまま目標にしやすい | 本人の目的に有効な場合だけ制度との接続候補を提示 |
| 行動計画 | ULが毎回考える | AIが候補を出し、本人とULが選択・修正 |
| 進捗確認 | 日付・内容をULが記憶 | 目標ごとの確認周期、未完了、障害を一覧化 |
| 1on1準備 | 複数記録を読み直して手作業要約 | 差分・未完了・質問候補をAIが事前整理 |
| 1on1後 | メモを転記し次回事項を再整理 | メモから構造化案を生成し、ULが確認して保存 |
| 本人確認 | 口頭確認が履歴に残らない | HTML提示と確認日時・方法・回答を記録 |
| 上位レビュー | 個別にULへ確認 | 全Unitを横断閲覧し、コメント・差戻し |

## 3. Memberの目標形成ジャーニー

### 3.1 共通開始

1. ULが対象Memberを選ぶ。
2. 本人との1on1で今回扱うテーマを確認する。
3. ULが本人の発言を「本人発言」として記録する。
4. UL所見は別欄へ記録する。
5. AIへ送る場合は匿名化プレビューを確認する。

### 3.2 目標がない人

```text
最近の経験・感情
→ 楽しかった / 苦痛だった / 達成感 / 不満
→ 大切にしたい生活・働き方
→ 興味・強み・避けたい状態
→ 仮説としての将来像
→ 次に試したい小さな行動
→ 振り返り
→ 仮説を更新
```

将来像を無理に確定させない。「分からない」を有効な状態として扱う。

### 3.3 目標が曖昧な人

```text
本人の目標案
→ AIが曖昧語・不足を検出
→ ULが質問候補を選ぶ
→ 本人へ確認
→ Why・達成基準・期限・現状差を補う
→ 行動へ分解
→ 本人確認
```

### 3.4 目標が明確な人

```text
目標・Why・期限・達成基準を直接入力
→ SMART監査
→ 不足項目だけ質問
→ 行動確認
→ 本人確認
```

自己分析の全工程を強制しない。

## 4. 目標確定後の継続ジャーニー

```text
目標確定
→ 行動開始
→ 目標固有の確認周期
→ 進捗・成果・障害を記録
→ AIが差分と次の質問を整理
→ 1on1
→ 継続 / 修正 / 保留 / 中止
→ 本人確認
→ 完了時の振り返り
→ 次の課題または休止
```

目標修正は失敗扱いにしない。環境・本人の希望・優先順位の変化に適応する正規フローとする。

## 5. ULの1on1ジャーニー

### 5.1 事前

1. 前回以降の進捗、行動、成果、障害、現場変化を集約する。
2. AIが差分、未完了、質問候補、修正候補を生成する。
3. ULが匿名化内容とAI出力を確認する。
4. ULが今回使う質問を選び、追加・削除・並べ替える。

### 5.2 実施中

1. 本人の発言を要点記録する。
2. AI提案を本人へ押し付けず、対話の補助に使う。
3. 事実、本人の希望、UL所見、未確認仮説を分ける。
4. 目標修正が必要なら、その場で確定せず確認案にする。

### 5.3 事後

1. 1on1メモをAIで構造化する。
2. ULが誤り、過剰推測、機密区分を確認する。
3. 本人と合意した事項、次の行動、UL支援、次回確認日を保存する。
4. 必要なHTMLを本人へ共有する。
5. 本人の回答を確認記録として残す。

## 6. 上位役職者ジャーニー

1. 全Unitの概要を確認する。
2. 目標未確認、長期未更新、1on1未実施等の運用状態を確認する。
3. 対象Unit・Memberの通常記録を閲覧する。
4. 機密記録は明示許可がなければ閲覧しない。
5. 元データを直接変更せず、レビューコメントまたは差戻しを行う。
6. ULの対応後、確認済み状態を付ける。

## 7. 本人確認ジャーニー

1. ULが本人確認用HTMLスナップショットを生成する。
2. 本人と対面・オンライン1on1で表示する、または期限付きURLを共有する。
3. 本人が承認、修正希望、保留を回答する。
4. ULが確認日時、方法、回答、修正内容を記録する。
5. 承認された内容だけを確定する。

本人向けHTMLに未承認AI推測、UL内部メモ、他Member情報、監査ログを含めない。

## 8. 例外ジャーニー

### AIが使えない

- 既存データの閲覧・編集・本人確認・HTML出力を継続する。
- ULが手動で目標・質問・SMART確認を入力できる。
- 復旧後も自動で未送信本文をAIへ送らない。

### 本人が目標を望まない

- 無理に目標を作成しない。
- 現在の困り事、維持したい状態、次回確認時期だけを記録できる。
- 会社制度上必要な対応は、本人の希望と分離して説明する。

### 本人の希望と会社要求が衝突する

- 両方を別の情報として記録する。
- AIに優先順位を決めさせない。
- ULが本人と対話し、必要なら社内支援者へ連携する。
