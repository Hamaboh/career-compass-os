# Phase 1: プロダクト定義

## 1. 文書の目的

本書は、Career Compass OSが誰のどの問題を、どの価値原則と業務境界で解決するかを定義する。Phase 0を上位入力とし、技術、DB、API、画面詳細、Prompt詳細は後続Phaseで確定する。

## 2. プロダクトコンセプト

> SESで分散常駐するメンバーについて、ULが本人の幸福・ライフプラン・キャリアプランを起点に対話し、AIの質問・整理・品質確認を利用して、本人が納得できる目標、行動、振り返りへつなげるLeader向けキャリア伴走支援OS。

本アプリは目標入力台帳ではない。AIが本人の意思を代行するシステムでも、会社の人事評価・給与決定システムでもない。

## 3. ビジョン

異なる客先で働き、日常的に一緒に仕事をしないULとメンバーであっても、本人の言葉、経験、感情、生活上の希望、キャリア上の希望、現場経験を継続的につなぎ、ULが整理作業ではなく対話と支援判断へ集中できる状態を実現する。

## 4. 最上位価値

優先順位は次とする。

1. 本人の安全・尊厳・幸福
2. 本人のライフプラン
3. 本人のキャリアプランと選択肢
4. 本人が説明できるWhyと納得感
5. 実行可能で検証可能な目標・行動
6. freeksの人事評価、Course、Grade、Unit Leaders Missionとの必要な接続

会社制度は本人の人生の目的ではない。本人の望む状態に近づくうえで制度上のキャリアアップが有効な場合にのみ、AIとULが関連を提示する。

## 5. 解決する中核課題

### 5.1 メンバー側の課題

- 将来どうなりたいか分からない。
- 仕事上の目標がない、または言語化できない。
- 生活上の希望と仕事上の選択が分離している。
- 過去の経験、感情、強み、価値観を整理できていない。
- 会社から示されたKPIや成長期待を、自分のWhyと接続できない。
- 目標を作っても具体的行動、達成基準、期限へ分解できない。
- 客先で得た経験が自社でのキャリア形成に蓄積されにくい。
- 振り返りが評価面談の直前だけになり、学びが失われる。

### 5.2 UL側の課題

- メンバーごとに目標設定品質がばらつく。
- 本人の希望を聞いたつもりでも、ULの解釈や会社都合へ寄りやすい。
- 目標をSMARTにする質問を毎回ゼロから考える必要がある。
- 前回記録、進捗、障害、現場状況を1on1前に手作業で整理している。
- 1on1後の記録、次回アクション、リマインドの整理に時間がかかる。
- 複数メンバーの確認時期と未完了事項を記憶・管理する負担がある。
- Unit Leaders Mission上の役割と、本人支援業務の関係が分断される。

### 5.3 組織側の課題

- 分散常駐によりメンバーの状況が見えにくい。
- 目標・1on1の質がUL個人の経験へ依存する。
- 会社制度資料がキャリア対話で適切に参照されない、または過度に優先される。
- 上位役職者が全Unitの支援状況を把握しにくい。
- 正式評価ではないキャリア伴走情報と、会社の人事判断が混同される危険がある。

## 6. 対象利用者

### 6.1 ログイン利用者

| 利用者 | 規模 | 主目的 |
|---|---:|---|
| Unit Leader | 約7人 | 自Unitメンバーのキャリア・目標・1on1支援 |
| 上位役職者 | 約5人 | 全Unitの状況閲覧、レビュー、差戻し、UL支援 |
| システム管理者 | 上記との兼任可 | 利用者、Unit、制度、AI、監査、運用設定 |

### 6.2 非ログイン関係者

| 関係者 | 関わり方 |
|---|---|
| Member本人 | 1on1と本人向けHTMLで内容を確認・修正・承認する |
| 社長 | 会社制度・評価ルールの最終更新責任者 |
| 必要な社内支援者 | UL判断でHRBP、Account Management、Board等へ連携する。MVPの直接利用者には含めない |

## 7. 提供価値

### 7.1 Member本人への価値

- 自分の生活と仕事を切り離さずに将来を考えられる。
- AIが決めた文章ではなく、本人が修正・承認した言葉を残せる。
- 現場経験が将来像、目標、成果として整理される。
- 会社制度を必要なときだけ自分のキャリアに結びつけられる。
- 目標と行動、進捗、振り返りを読みやすいHTMLで確認できる。

### 7.2 ULへの価値

- 本人へ聞くべき質問、曖昧さ、矛盾、SMART不足をAIが提示する。
- 1on1前後の情報整理・文章化を短縮できる。
- 確認漏れ、未完了行動、停滞、次回確認事項を一元管理できる。
- 本人の事実とAI推測、UL所見を混同せずに管理できる。
- 自Unitのメンバーだけを安全に扱える。

### 7.3 上位役職者への価値

- 全Unitの目標・進捗・1on1運用状況を横断して閲覧できる。
- 元データを書き換えずにレビュー、コメント、差戻しができる。
- ULごとの業務負荷や支援上の詰まりを把握できる。
- 正式人事評価とキャリア伴走記録を混同せずに確認できる。

## 8. 成功状態

### 8.1 定性的成功

- 本人が目標を自分の言葉で説明できる。
- 本人の幸福・生活・キャリアと目標のつながりを確認できる。
- ULがAI出力を鵜呑みにせず、対話に利用できる。
- 会社制度が本人の目的へ置き換わっていない。
- ULが準備・転記より本人との対話へ時間を使える。

### 8.2 定量的な検証仮説

| 指標 | MVP後の検証目標 |
|---|---|
| 1on1準備時間 | 導入前比50%以上削減 |
| 1on1後の記録時間 | 導入前比40%以上削減 |
| 目標作成・修正時間 | 導入前比30%以上削減 |
| 本人未確認の正式目標 | 0件 |
| AIが自動確定した目標・評価 | 0件 |
| Unit越境アクセス | 0件 |
| 匿名化確認を経ない外部AI送信 | 0件 |
| AI費用 | 月間上限1,000円相当以内 |

数値目標は運用検証用であり、人事評価指標にしない。

## 9. 非目的

MVPの非目的は次である。

- 正式な人事評価の確定
- 給与・単価計算
- 昇格・Course変更の自動判定
- Member本人向けセルフサービス
- 自由登録、招待、OTP、アプリ独自パスワード
- Slack・メール・勤怠・SmartHR等の自動連携
- AIによる心理診断、医療判断、離職予測、人材選別
- AIによる本人への自動通知・自動介入
- 会社制度への目標接続の強制

## 10. 制約

- Member本人はMVPでログインしない。
- ULが本人の回答・承認を代理入力するため、事実・所見・推測の分離が必須である。
- 個人・会社・顧客・案件・人事制度固有情報は匿名化せず外部AIへ送れない。
- ULが匿名化後の送信内容を毎回確認する。
- AIモデルは低価格を優先し、PoCで決める。
- 約12人規模で最小コストを目指す。
- 新Design Freezeまでは実装しない。

## 11. プロダクト原則

1. 本人に考えさせすぎないが、AIが決めすぎない。
2. 本人の言葉を最優先し、AI推測を明示する。
3. 会社制度は選択肢と参考情報であり、人生の目的にしない。
4. ULの判断を支援し、置き換えない。
5. 入力のための入力を避け、1on1前後の再利用を優先する。
6. 未確定情報を未確定のまま安全に保存できる。
7. 機密情報は必要最小限の人にだけ見せる。
8. AI停止時も既存記録の閲覧・編集・共有を継続できる。
