# Phase 0: 一次資料・設計基準

## 1. 文書の目的

本書は、Career Compass OSの再設計に使用する一次資料、情報の優先順位、資料から確認できる事実、利用者が明示的に確定した補正ルールを定義する。

本Phase 0はコード実装を許可するDesign Freezeではない。旧Phase 1〜4、旧補助仕様、旧ADRは履歴資料として保持するが、Phase 1〜5の再設計が完了するまで実装根拠として使用してはならない。

## 2. 設計情報の優先順位

矛盾がある場合は、次の順序で優先する。

1. 利用者が本再設計セッションで明示的に確定した決定
2. 本Phase 0文書群
3. Google Drive上の会社制度原本
4. 今後作成する新Phase 1〜4
5. 新Design Freeze
6. 旧Phase 1〜4、旧Design Freeze、旧補助仕様、旧ADR（履歴参照のみ）

新Design Freeze完成後は、新Design Freezeを実装仕様の最上位とする。

## 4. 資料の責任境界

### 4.1 個人評価

- 根拠資料は人事評価・給与制度PDFである。
- Unit Leader本人もエンジニア個人として対象になる。
- ビジネスマナー、現場評価、定性評価、会社貢献、Course、Grade等を含む。

### 4.2 Unit Leader評価

- 根拠資料はUnit Leaders Missionである。
- Unitという組織に対する管理・教育・カルチャー・エンゲージメント・MVV体現等を扱う。
- 個人評価とは独立して評価される。

### 4.3 アプリの境界

- 本アプリは会社の正式な人事評価・給与決定ツールではない。
- 本アプリの主目的は本人の幸福、ライフプラン、キャリアプランと納得感ある目標形成の支援、およびUL業務の効率化である。
- 会社制度は本人のキャリア実現に必要な場合のみ参照し、目標への接続を強制しない。
- AIは人事評価、昇格、給与、Course変更を決定しない。

## 5. 原本より優先する補正ルール

| 項目 | 正式ルール | 理由 |
|---|---|---|
| 交通費提出期限 | 翌月2営業日目 | 原本が未修正。利用者が現行ルールを明示 |
| 営業日 | 土曜日・日曜日・日本の祝日を除く | 本再設計で確定 |
| レスポンススピード | 業務連絡に24時間応答がない場合 | 利用者が正式値を確認 |

交通費期限はAIで計算せず、決定論的ロジックで算出する。

## 6. draftの範囲

- `Category = Management`に属するKPIのみdraftである。
- 現時点ではManagement役職の実就任者がいないため草案扱いである。
- LeaderカテゴリーのKPIはdraftではない。
- Management KPIは通常のAI Context、正式評価参考値、自動判定に使用しない。
- 社長による正式化後、新しい制度バージョンとして有効化する。

## 7. 制度更新責任

- 会社制度・評価ルールの最終更新責任者は社長とする。
- 原本の更新だけでアプリ内の過去データを自動変更しない。
- 目標、参考計算、レポートは参照した制度バージョンを固定する。
- 新制度を過去へ遡及適用する場合は、明示操作、理由、実行者、対象範囲を監査記録に残す。

## 8. 資料取込ルール

- Drive原本を実行時に無制限取得する設計にはしない。
- 原本ID、版、更新日時、適用期間、取込日時、取込者を記録する。
- AIに参照させる制度情報は構造化・版管理し、必要な最小範囲だけをContextに含める。
- 会社固有用語、人名、顧客名、案件名、人事評価用語はAI外部送信前の匿名化対象とする。

## 9. Phase 0完了条件

- 一次資料が一意に特定されている。
- 資料間の責任境界が定義されている。
- 利用者の補正ルールが記録されている。
- draftと正式制度が区別されている。
- 旧設計が実装根拠ではないことが明示されている。
- Phase 1以降が参照できる確定事項と暫定事項が分離されている。
