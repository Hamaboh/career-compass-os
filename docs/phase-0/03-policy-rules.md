# Phase 0: 制度・計算・運用ルール

## 1. 本書の範囲

本書は一次資料および利用者の明示決定から、後工程で失ってはならない制度・計算・運用ルールを定義する。アプリは会社の正式評価を確定せず、本書に基づく値も原則として参考情報として表示する。

## 2. 評価の二層分離

### 2.1 個人評価

- 対象: 全社員。UL本人を含む。
- 原本: 人事評価・給与制度PDF。
- 意味: エンジニア個人として受ける会社評価。

### 2.2 UL評価

- 対象: Unit Leader。
- 原本: Unit Leaders Mission。
- 意味: Unit運営・マネジメントに対して受ける会社評価。

### 2.3 禁止する統合

- 一方の達成をもう一方の達成として扱わない。
- 一方の未達をもう一方の未達として扱わない。
- 個人キャリア目標とUnit KPIを常に親子関係にしない。
- AIに両評価の最終結果を統合・決定させない。

## 3. ビジネスマナー関連の補正

### 3.1 交通費

- 期限: 対象月の翌月2営業日目。
- 営業日: 土曜日、日曜日、日本の祝日を除く日。
- 資料にある固定日付は使用しない。
- 計算は決定論的に行い、AIを使用しない。

### 3.2 レスポンススピード

- 業務連絡に24時間応答がない場合を評価イベントの対象とする。
- MVPではSlack・メールの自動監視を行わず、ULが事実を記録する。
- AIは事実を作成せず、記録された情報の整理だけを行う。

## 4. 評価期間

| 名称 | 開始日 | 終了日 |
|---|---|---|
| 上期 | 1月1日 | 6月30日 |
| 下期 | 7月1日 | 12月31日 |

- 制度版、人数スナップショット、算定結果、確定・ロック状態を期間単位で保持する。
- 過去期間は制度更新で自動再計算しない。

## 5. 退職率

### 5.1 式

```text
平均メンバー数 = (期首対象人数 + 期末対象人数) / 2
退職率 = 期間内退職者数 / 平均メンバー数 * 100
```

平均メンバー数が0の場合、退職率は`算出不能`とする。

### 5.2 所属・状態

- 別Unitへの異動は退職者に数えない。
- 会社自体を退職した時点の主所属Unitに退職者として数える。
- 兼務者は主所属Unitにだけ数える。
- 休職者は期首・期末の対象人数から除外する。
- 退職後に再入社しても過去の退職イベントは取り消さない。このルールは暫定である。
- Unit統合・分割時は評価期間期末の主所属Unitを所属対象とする。このルールは暫定である。

### 5.3 8名以上のUnit

- 平均メンバー数が8.0以上であることを意味する。
- 期首人数または期末人数だけで判定しない。

### 5.4 数値表示

- 画面・レポートでは小数第1位まで表示する。
- 小数第2位以下は切り捨てる。
- 元の分子・分母と、丸め前の内部値を保持する。
- 本アプリは正式な人事評価を確定しないため、表示値を会社の確定評価として扱わない。

## 6. Management KPI

- `Category = Management`のKPIのみdraftである。
- Leader KPIはdraftではない。
- draftは現在の正式評価、自動判定、通常のAI Contextに使用しない。
- 将来正式化する場合は、新しい制度バージョンとして登録する。

## 7. 本人確認

### 7.1 目標状態

```text
下書き
→ AI提案生成済み
→ UL確認済み
→ 本人確認待ち
→ 本人修正希望 / 保留
→ 本人確認済み
→ 確定
→ 実行中
→ 完了 / 中止
```

- 本人確認前でも下書き・暫定進捗は保存できる。
- 本人確認前の目標を正式目標として集計・表示しない。
- 本人の電子署名はMVPで要求しない。
- ULが確認日時、方法、本人の回答を記録する。

### 7.2 本人向けHTML

含められるもの:

- 本人確認済みの将来像、Why、目標
- SMART結果、行動、進捗、成果、振り返り
- 本人と合意した1on1内容
- 必要な制度との接続

含めないもの:

- 未承認のAI推測
- UL内部メモ
- 人事判断用メモ
- 監査ログ
- 他メンバーを識別できる情報

## 8. 共有

- 共有URLの既定有効期限は7日、最大30日。
- 推測困難なトークンを使用し、保存時はハッシュ化する。
- 手動失効を可能にする。
- 期限切れ・失効済みはサーバー側で拒否する。
- 検索エンジン登録と共有レスポンスの不適切なキャッシュを禁止する。
- 発行、閲覧、失効を監査する。

## 9. 保持・匿名化

| データ | ルール |
|---|---|
| 在籍中の確定目標・進捗・1on1 | 継続保存 |
| 退職・管理対象外後の個人データ | 1年間保存後、匿名化 |
| 匿名化後 | 個人を復元できない統計だけを保持 |
| 監査ログ | 3年間 |
| 不採用AI提案 | 生成から1年、または目標終了後6か月の早い方 |
| 共有URL | 期限後または失効後ただちに利用不可 |

## 10. バックアップ・復旧

- 日次バックアップ。
- 30日保持。
- 初期RPOは24時間。
- 初期RTOは1営業日。
- バックアップアクセスはシステム管理者に限定する。
- 復旧手順と定期復旧テストをPhase 3・4で定義する。

## 11. 監査

- ULは自分と自Unitに関する監査ログを閲覧できる。
- 上位役職者は全Unitの監査ログを閲覧できる。
- システム管理者は全件を閲覧できる。
- 監査ログ経由で権限外本文を漏えいさせない。
- 目標本文・1on1本文・AI Prompt本文を監査ログへ無制限複製しない。

## 12. 暫定規則の変更

- 暫定規則には状態、決定理由、決定日、決定者を保持する。
- 社長が正式規則を定めたら新しい制度版を作成する。
- 過去結果を無断で遡及変更しない。
