# @career-compass/shared

フロントエンド（apps/web）とバックエンド（apps/api）の両方から参照する、**Phase2/Phase3で確定した語彙をそのままコード化したもの**。

## なぜこのパッケージがあるか

design freeze（[../../docs/DESIGN_FREEZE.md](../../docs/DESIGN_FREEZE.md)）のルール4「既存設計との整合性を最優先する」を、レビュー任せではなくコンパイラで機械的に担保するための場所。たとえば:

- Phase2 FOUNDATION §0.2の9値ステータス語彙を、フロント・バック双方で同じ文字列リテラル型として使う（どちらかが独自の状態名を書いてしまう事故を型エラーとして検出する）。
- Phase3 7.1のRBAC権限フラグ名を定数として共有し、Guard実装とフロントの表示制御（10.1節「権限がない場合は導線を出さない」）が同じ名前を参照するようにする。

## 現在の中身（Step -1）

- `status.ts` … Phase2 §0.2 目標階層オブジェクトの9値ステータス
- `source.ts` … Phase2 §0.3 `user_stated` / `ai_inferred` の区別（+ `user_approved`）
- `agents.ts` … Phase2 §0.6 予約エージェント名（13種、これ以外の新規AIエージェント名を作らない）
- `rbac.ts` … Phase3 7.1 権限フラグ

## ビルドについて

このパッケージは今のところビルド成果物を持たず、TypeScriptソースをそのままワークスペース経由で参照する。NestJS/Next.jsのビルドパイプラインがこのままで不都合になった場合（型のみで完結せず実行時コードが増えてきた場合等）は、tsup等での事前ビルド化を検討する。DB/API/権限モデルに影響しない範囲の変更のため、design freezeルール1（軽微な実装上の変更）の範囲で対応してよい。
